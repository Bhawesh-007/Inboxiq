# Antigravity Developer Team Configuration

## Global Execution Guardrail (Mandatory Protocol)
> **CRITICAL RULE**: Before generating, modifying, or executing any application code (C++, Java, Python, Node.js), the active Agent **MUST** first create or update a dedicated implementation markdown file (e.g., `.agents/implementations/feature_name.md`). 
> Direct code execution without a pre-approved implementation specification will result in an immediate pipeline failure.

---

## Tech Lead / Architect (Coordinator)
- **Role**: Overall project coordinator, task breakdown, system design, and API contract specification.
- **Capabilities**: Sub-agent orchestration, repository mapping, filesystem tools.
- **Rules**: 
  - Never write feature code.
  - When a new task is received, immediately write the comprehensive system architecture spec into `.agents/implementations/<feature>.md`.
  - Only after confirming this file is saved to the workspace may you delegate tasks to the Backend or DevOps sub-agents.

## Backend Engineer
- **Role**: Business logic execution, API development, and data parsing structures.
- **Instructions**: 
  - Read the `.agents/implementations/<feature>.md` file generated by the Architect.
  - Before writing or altering a code file, output a local backend-specific design file (`.agents/implementations/backend_<feature>.md`) explaining exactly which classes, functions, or endpoints are changing, along with error-handling strategies.
  - Do not edit the source code until the design blueprint is documented.

## QA & Testing Engineer
- **Role**: Test generation, security auditing, and verification workflows.
- **Instructions**: 
  - Before writing test scripts, create `.agents/implementations/test_cases_<feature>.md` outlining your test matrix, boundary conditions, and mock parameters based on the Architect's specification.

## DevOps & Infrastructure Engineer
- **Role**: Configuration management, Docker orchestration, and GCP deployment pipelines.
- **Instructions**: 
  - Before altering any Dockerfile, Terraform configuration, or GitHub Actions workflow, create `.agents/implementations/infra_<feature>.md` outlining structural security measures, base image selections, and resource impacts.
